# SpotFit · 박성은 STEP 4 대시보드

2025년 서울 자료에서 **희망 업종 안의 상권을 비교**합니다. 네 영역은 매출 잠재력·경쟁·안정성·수요입니다. 창업 성공 확률·순이익·예산 적합성을 판단하지 않으며, 성장성은 산출하지 않습니다.

김지영 님의 공통 데이터와 이승희 님의 STEP 4 구현을 출처와 함께 재사용했습니다. 이 폴더에서는 입력을 독립 검증하고 점수표를 다시 생성했으며, 2026-11-09 강사 피드백을 반영했습니다. 새로운 원천 데이터나 새로운 분석 모형을 수집·개발한 것으로 주장하지 않습니다.

## 실행

팀 저장소 최신 main 전체를 받은 뒤 저장소 루트에서 실행합니다. [uv](https://docs.astral.sh/uv/)가 필요합니다. 원본 `data/raw/`는 필요 없습니다.

```powershell
uv run --project "박성은/step4_dashboard" python "박성은/step4_dashboard/build_scores.py"
uv run --project "박성은/step4_dashboard" python -m marimo run "박성은/step4_dashboard/app.py"
Start-Process ".\박성은\step4_dashboard\report\04_상권비교점수_대시보드_2025.html"
```

Windows에서는 이 폴더의 `대시보드_실행.cmd`를 더블클릭해도 됩니다. 브라우저에 나오는 주소를 열고, 종료할 때는 실행 창에서 Ctrl+C를 누릅니다.

## 화면 사용법

1. 희망 업종을 고르고 자치구·상권 유형으로 표시 범위를 좁힙니다. 백분위는 항상 서울 전체 같은 업종 기준입니다.
2. 기본 가중치는 매출 30·경쟁 25·안정성 15·수요 30입니다. 슬라이더로 바꿀 수 있으며 **팀 미확정 가정**입니다.
3. 수요의 주 고객층은 세 값 평균·유동인구·직장인·주민 중 고릅니다. 구성 지표와 원값은 상세 표에서 확인합니다.
4. 경계 지도를 클릭하거나 비교표에서 행을 선택한 다음 상권 상세 탭을 엽니다. 배경 지도는 확대·이동용이며, 두 지도는 선택한 하나만 생성합니다.
5. 상세에서는 실제 업종 중앙값을 표시한 막대와 레이더를 함께 봅니다. 레이더의 결측은 0점으로 연결하지 않습니다. 최대 4개 상권을 같은 축의 작은 막대로 비교할 수 있습니다.

## 점수 기준과 가정

| 영역 | 사용 지표 | 높은 점수의 뜻 |
|---|---|---|
| 매출 잠재력 | 점포당 월매출, 매출 4개 분기 관측 | 같은 업종에서 매출 대리지표가 높음 |
| 경쟁 [가정] | 평균 점포 ÷ (유동인구/1,000) | 수요 대비 같은 업종 점포가 적음 |
| 안정성 · 신뢰도 낮음 | 연간 폐업 건수/4분기 평균 점포를 업종 평균 쪽으로 축소 추정 | 보정 폐업률이 낮음 |
| 수요 [가정] | 면적당 인구의 업종 내 백분위, 주 고객층 선택 | 선택한 수요 지표가 높음 |

관광특구 6곳은 제외합니다. 평균 점포 5개 이상이고 업종의 비교 상권이 30곳 이상인 경우만 점수를 만듭니다. 매출 영역에도 유효 비교 상권 30곳 기준을 적용합니다. 결측은 0으로 채우지 않고, 자료가 있는 영역의 가중치를 다시 나눕니다. 계산 영역 수도 표시합니다. 5개·30곳은 팀 운영 기준이며 통계적 신뢰성을 보장하지 않습니다.

공통 데이터의 평균 점포·폐업률·축소 추정을 분기 패널에서 다시 계산해 확인했습니다. 4분기 평균 분모와 일치하여 재사용합니다. 분기 매출 증감률은 연속 분기에만 계산하고 상하위 5% 경계로 잘라 참고 표시합니다. 점수나 성장성에는 사용하지 않습니다.

유동인구는 자료의 집계량이며 고유 방문자 수나 구매전환율이 아닙니다. 직장·상주인구·집객시설은 2025년 중 변하지 않습니다. 화면의 마지막 값 변경 분기와 실제 통계 기준 시점은 다를 수 있습니다. 실제 통계 시점은 미확인입니다.

금융 MBTI 유형별 가중치는 구현하지 않았습니다. 유형표가 확정되면 연결한다는 안내를 유지합니다.

## 검증과 성능

```powershell
uv run --project "박성은/step4_dashboard" python "박성은/step4_dashboard/test_step4.py"
uv run --project "박성은/step4_dashboard" python -m marimo check "박성은/step4_dashboard/app.py"
uv run --project "박성은/step4_dashboard" python "박성은/step4_dashboard/verify_exports.py"
uv run --project "박성은/step4_dashboard" python "박성은/step4_dashboard/benchmark.py"
```

검증 근거는 `report/core_validation.json`, `report/export_validation.json`, `report/static_check.json`에 있습니다. 다른 탭을 숨기는 `ancestor-stopped`는 실제 셀 오류와 구분합니다.

분기 지표와 지도용 정적 데이터를 `build_scores.py`에서 미리 저장합니다. 앱은 데이터 로드를 한 번만 하고, 최근 64개 필터·가중치 조합의 점수 조회 결과를 메모리에 저장합니다. **입력을 갱신하면 build_scores.py를 실행하고 앱을 재시작**해야 합니다. 성능 수치는 `report/performance.json`에 있으며 Python 처리·직렬화 시간과 브라우저 렌더링 시간을 구분합니다.
