# Spotfit marimo 대시보드

2025년 서울 상권 EDA와 STEP 2·3 산출물을 탐색하는 대시보드다. 업종·분기·자치구·상권 유형·최소 점포 수를 바꾸면 지표와 차트가 갱신된다.

## 실행

macOS에서는 [대시보드 실행.command](대시보드%20실행.command)를 실행한다. 터미널 창을 닫으면 서버도 종료된다. 터미널에서 직접 실행하려면:

```bash
cd seoul-commercial-analysis
.venv/bin/marimo run 김지영/dashboard/app.py --port 2720
```

브라우저에서 `http://localhost:2720`을 연다. 중지하려면 실행 터미널에서 `Ctrl+C`를 누른다. 2720 포트를 다른 앱이 사용 중이면 `--port 2721`처럼 다른 포트를 지정한다.

필요 패키지는 기존 프로젝트 가상환경에 설치했다. 다른 환경에서 설치할 때는:

```bash
cd seoul-commercial-analysis
python3 -m venv .venv  # 가상환경이 없을 때만
.venv/bin/python -m pip install -r 김지영/dashboard/requirements.txt
```

코드와 화면을 함께 편집하려면:

```bash
.venv/bin/marimo edit 김지영/dashboard/app.py --port 2720
```

marimo 공식 실행 방식은 [앱 실행 문서](https://docs.marimo.io/guides/apps/)를 참고했다. 이 대시보드는 로컬 Python 앱이며 외부 서비스에 데이터를 업로드하지 않는다.

## 화면 구성

| 화면 | 할 수 있는 일 |
| --- | --- |
| 상단 지표 | 조건에 맞는 상권 수·점포 수·관측 매출·점포당 월 환산 중앙값 확인 |
| 상권 비교 | 대표 위치 지도, 상위 12개, 분기 흐름, 점포와 매출 관계, 검색·정렬 표, 현재 표 CSV 저장 |
| 선택 상권 상세 | 분기별 매출·개폐업, 완전 연매출·변동계수, 상권 수요·시설 확인 |
| 고객·소비 시간 | 선택 상권·업종·분기의 시간대·연령·요일별 매출 구성 |
| EDA 그림 모음 | 기존 EDA 31개 그림과 쉬운 해설. 이 탭은 상단 필터와 독립적 |
| 데이터 확인 | 현재 조건의 매출 보유 상태, 지표 정의와 해석, 파생변수 사전 |

기본값은 **커피-음료·2025년 4분기·서울 전체·점포 5개 이상**이다. 다른 업종도 모두 선택할 수 있다. 화면의 ‘자세히 볼 상권’ 선택은 상세·고객 탭에 적용되며 전체 비교 차트의 범위를 한 상권으로 좁히지 않는다.

## 읽는 기준

- 관광특구는 주요 비교에서 제외한다.
- 매출이 없는 칸과 실제 매출 0을 구분한다. 미제공 업종도 점포·개폐업은 볼 수 있다.
- 관측 매출은 보이는 칸만의 합계다. 선택한 모든 상권의 실제 매출이나 순이익이 아니다.
- 월 환산은 분기 매출÷전체 점포 수÷3이다. 각 상권의 환산값을 구한 후 중앙값을 보여 준다.
- 분기 추이는 매 분기 같은 필터를 다시 적용하므로 포함 상권이 달라질 수 있다. 전년 성장률이 아니다.
- 업종 중앙값 배율은 STEP 3에서 만든 **서울 전체·같은 업종·같은 분기** 기준이다. 지역 필터로 분모를 다시 계산하지 않는다.
- 지도는 대표점과 단순화한 상권 경계를 표시하며 배경 타일은 사용하지 않는다. 점의 색은 매출 관측 여부다. 매출 크기·상권 면적과 무관하다.
- 인구·시설은 업종 행을 합산하지 않고 상권×분기 context에서 한 번 연결한다. 실제 통계 작성시점은 미확인이다.
- 필터 후 자료가 없으면 빈 결과를 안내한다. 확인되지 않은 추천 점수와 예산 적합성은 만들지 않았다.

## 데이터와 파일

대시보드는 `../step2_3/data/`의 fact·context·annual 압축 CSV와 변수 사전·manifest를 읽는다. 기존 데이터를 읽기만 하며 바꾸지 않는다. 패키지는 캐시된 DataFrame을 재사용하므로 STEP 2·3 데이터를 다시 생성한 뒤에는 서버를 재시작한다.

`assets/trdar_points.csv`와 `assets/trdar_outlines.json`은 현재 K03 경계에서 추출한 표시용 지도 자료다. 대표점은 도형 내부의 점이며 실제 점포 위치가 아니다. 경계는 EPSG:5181에서 20m 허용오차로 단순화 후 WGS84로 변환했다. 원본 도형은 바꾸지 않았다. 경계가 바뀌면 두 지도 파일도 다시 만들어야 한다.

- `app.py`: marimo 화면 및 반응형 필터
- `dashboard_data.py`: 데이터 처리·차트 함수
- `requirements.txt`: 대시보드 추가 의존성
- `test_dashboard.py`: 필터·자료 부재·집계 의미·차트 생성 검증
- [EDA 보고서](../eda%28Codex%29.md)
- [STEP 2 설계](../STEP2%28Codex%29.md), [STEP 3 설계](../STEP3%28Codex%29.md)

STEP 2·3 결과가 없으면 먼저 해당 전처리 코드를 실행해야 한다. 기존 EDA 그림이 없어도 핵심 비교 기능은 실행할 수 있다.

## 검증

```bash
.venv/bin/marimo check 김지영/dashboard/app.py
.venv/bin/python 김지영/dashboard/test_dashboard.py
.venv/bin/marimo export html 김지영/dashboard/app.py -o /tmp/spotfit-dashboard.html
```

검증 완료: marimo 정적 검사, 기본 화면·매출 미제공 업종·실제 빈 결과 화면의 전체 셀 실행 및 HTML export, 대표 필터/매출 미제공 업종/빈 결과/실제 0원 보존 등 테스트 6개. HTML export는 저장 시점의 정적 스냅숏이며 필터를 바꿔 재계산하는 앱과 다르다. [공식 HTML 내보내기 안내](https://docs.marimo.io/guides/exporting/) 참고.

브라우저 자동 제어 권한이 없어 실제 화면의 클릭·배치 검증은 수행하지 못했다. 로컬 서버 실행과 기본 앱 계산은 확인했다.
