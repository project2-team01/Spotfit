## 6. 업종코드·상권코드 주의사항

- **코드는 문자열로 읽으세요.** 상권 코드(예: `3110008`), 행정동 코드(8자리), 법정동 코드(10자리), PNU(19자리), 건물관리번호(25자리)를 숫자로 읽으면 자릿수나 정밀도를 잃습니다. S01 신우편번호는 `05241`처럼 선행 0이 있습니다.
- **두 기관의 업종 체계가 다릅니다.**
  - S01: 상권업종분류 대 10, 중 75, 소 247 (예: `I21006 치킨`). 표준산업분류(10차) 코드도 함께 있습니다. 표준산업분류코드는 199행이 비어 있습니다.
  - 서울: 서비스업종 100개. K02 기준 외식 `CS1` 10개, 서비스 `CS2` 47개, 소매 `CS3` 43개입니다. 포털 FAQ의 생활밀접업종 100개 설명과 같습니다.
  - K01 추정매출은 100개 중 **62개 업종만** 제공합니다. 변호사사무소, 세무사사무소, 독서실, 여행사 등 38개는 매출 행이 없습니다.
- **S01 대분류 이름**: 실제 데이터는 10개입니다(음식, 소매, 과학·기술, 수리·개인, 교육, 부동산, 시설관리·임대, 예술·스포츠, 보건의료, 숙박). ZIP 안 `[필독]파일열람방법.txt`에는 개편 전 대분류 8개가 적혀 있습니다. 안내문 쪽이 오래된 내용입니다.
- **S01 상가업소번호는 2023년 업종 개편 때 새로 만들어졌습니다.** 개편 이전 릴리스와는 점포 단위로 연결할 수 없습니다(S02 포털 안내).
- **상권 구분 코드**: `A` 골목상권 1,090개, `D` 발달상권 249개, `R` 전통시장 305개, `U` 관광특구 6개. 합계 1,650개입니다.
- **K02 헤더는 영문 소문자이고 순서가 Open API 명세와 다릅니다.**
  - `similr_induty_stor_co`가 전체 점포 수입니다. 필드명은 "유사업종 점포 수"처럼 보입니다.
  - 304,775행 모두에서 `similr_induty_stor_co = stor_co + frc_stor_co`가 성립합니다. 따라서 `stor_co`는 일반 점포 수입니다.
  - `opbiz_rt`, `clsbiz_rt`는 최대 200, 450까지 있습니다. 100을 넘으므로 계산식 확인이 필요합니다.
- **K01 컬럼명 주의**
  - 시간대별 건수 6개 컬럼명이 `시간대_건수~06_매출_건수`처럼 깨져 있습니다. 순서상 00~06, 06~11, 11~14, 14~17, 17~21, 21~24입니다. 가공 데이터에서 이름을 바꾸고 원본은 그대로 두세요.
  - `당월_매출_금액`은 이름과 달리 분기 매출입니다(포털 FAQ).
  - 남성+여성 매출 합은 총매출보다 작은 경우가 많습니다(중앙값 98.6%). 법인 매출에 성별이 없어서입니다(포털 FAQ).

- **EPSG:5186과 혼동하지 마세요.** 5186은 False Northing이 600,000입니다. 이 파일의 `.prj`는 500,000이므로 5181입니다.
- `.prj`가 ESRI WKT라 일부 도구가 EPSG 코드를 자동 인식하지 못할 수 있습니다. 읽은 뒤 `k03.set_crs(5181, allow_override=True)`로 명시하는 것을 권장합니다.
- 공간 조인은 S01 점을 5181로 바꾸거나 K03을 4326으로 바꾼 뒤 수행합니다. 면적·거리 계산은 5181(미터)에서 하세요.
- `RELM_AR`(영역 면적)은 최소 1,854, 최대 2,462,734입니다. 단위는 ㎡로 추정되며 폴리곤 면적과 대조해 확인이 필요합니다.
- 도형 유효성(자기교차 등)은 이번 단계에서 점검하지 않았습니다. 표준 라이브러리로 헤더와 DBF만 읽었습니다.
- K03 ZIP 수정일은 2023-10-23입니다. 그래도 상권 코드 1,650개는 2025년 K02·K04 코드와 정확히 같습니다.

## 10. STEP 2에서 확인할 사항

1. 인코딩을 지정해 읽습니다. S01은 UTF-8, S02와 서울 CSV는 CP949, K03 DBF는 UTF-8입니다.
2. 코드 컬럼은 모두 문자열로 다룹니다.
3. K05~K07에서 2025년 행만 고릅니다.
4. K05 공백을 0으로 볼지 결정하고 근거를 남깁니다.
5. K05 `집객시설_수`의 정의를 확인하거나 하위 시설 수를 따로 씁니다.
6. K01 시간대 건수 컬럼명과 K02 영문 헤더를 가공 데이터에서 통일합니다.
7. K02 개업률·폐업률이 100을 넘는 이유를 확인합니다.
8. S01 업종(247)과 서울 서비스업종(100)의 매핑표를 만듭니다. K01은 62개 업종만 있다는 점을 반영합니다.
9. S01 점포를 K03 상권에 공간 조인합니다. 어느 상권에도 속하지 않는 점포의 처리 방침을 정합니다.
10. 행정동 코드 결합 대신 공간 조인을 우선 검토합니다. 행정동 코드를 쓰면 상일동 분동 같은 불일치를 처리해야 합니다.
11. K03 도형 유효성과 `RELM_AR` 단위를 확인합니다.
12. 2025년 4분기 서울 자료와 S01 2025-12-31 스냅숏을 같은 시점으로 볼지 정합니다.

## 11. 대용량 데이터 공유 방법

- `data/raw/`는 약 734 MB입니다. 100 MB를 넘는 파일이 2개 있습니다.
  - `semas_store_20251231.zip` (339,048,114 B)
  - 압축 해제한 서울 CSV (291,391,584 B)
- GitHub 일반 업로드의 파일당 100 MB 한도를 넘으므로 `data/raw/`는 `.gitignore`로 제외했습니다.
- 권장 공유 방식
  1. 팀 공유 드라이브에 `data/raw/` 폴더를 그대로 올립니다.
  2. Git에는 `scripts/`, `data/metadata/`, `docs/`, `README.md`만 올립니다.
  3. 팀원은 공유 드라이브에서 받은 뒤 프로젝트 폴더에서 `shasum -a 256 -c data/metadata/checksums.sha256`으로 확인합니다.
  4. 공유 드라이브를 쓸 수 없으면 `python3 scripts/download_data.py`로 공식 출처에서 다시 받습니다. 서버 파일이 갱신됐다면 해시가 다를 수 있습니다.
- Git LFS도 가능하지만 저장 용량과 전송량 한도가 있어 팀 공유용으로는 권장하지 않습니다. 한도는 GitHub 요금제 문서를 확인하세요.
